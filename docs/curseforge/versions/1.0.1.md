<h2>v1.0.1 - Arm Visibility Fix &amp; Weapon Effects</h2>

<h3>Fix</h3>
<ul>
<li><strong>Arm visibility toggle keeps animation running</strong>: setting <code>isShowingArmsInFirstPerson</code> to false no longer disables the first-person animation entirely. Arms become invisible but the weapon continues to animate normally.</li>
<li><strong>First-person enabled check</strong>: <code>isFirstPersonEnabled()</code> no longer depends on <code>IS_SHOWING_ARMS_IN_FIRST_PERSON</code> — <code>FIRST_PERSON_ANIMATIONS</code> config works independently.</li>
</ul>

<h3>New</h3>
<ul>
<li><strong>Weapon trail particles</strong> (<code>isShowingWeaponTrails</code>): sparks appear along the swing arc during attacks.</li>
<li><strong>Visual slash effects</strong> (<code>isShowingSlashEffects</code>): end rod particles burst at the weapon tip on each swing.</li>
<li>Both effects are independently configurable and can be combined or used separately.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>CombatAnimationController.getFirstPersonMode()</code> always returns <code>THIRD_PERSON_MODEL</code> during attacks — arm visibility controlled via <code>FirstPersonConfiguration.setShowRightArm()</code>/<code>setShowLeftArm()</code></li>
<li><code>WeaponEffectManager</code>: tracks active attacks, calculates swing position from preset arc, spawns particles each tick</li>
<li><code>SwingArc</code> enum: defines swing curves for each preset type (horizontal, vertical, stab, slam, spin, etc.)</li>
<li>Attack speed modifier now applies before triggering weapon effects in <code>handleAttackAnimation()</code></li>
</ul>
